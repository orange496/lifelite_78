# 五看三定：LifeLite 的产品分析

「五看三定」是华为做战略规划时常用的一套框架：先看行业、市场、客户、竞争、自己，再定战略控制点、目标、策略。这里借它把 LifeLite 的定位与取舍讲清楚——**不是给作业凑格式，而是解释我们为什么只做这些功能**。

---

## 一、五看

### 1. 看行业：自我管理工具正在「轻量化」

目标管理 / 习惯养成是一个成熟且拥挤的赛道。过去十年的演化方向很清楚：

- 从「功能大而全」到「只解决一个动作」——Notion 模板太自由，很多人搭完模板就再也没打开过；
- 从「强提醒」到「弱陪伴」——番茄钟的强制锁机对一部分人有效，对另一部分人只是卸载理由；
- 从「云端账号」到「本地优先」——隐私意识抬头，越来越多人不想为了记几个目标注册账号。

**结论**：这个赛道的增量不在「更多功能」，而在「更低的使用门槛」和「更即时的正反馈」。这正好是一个小团队用单个 HTML 页面也能做出差异化的方向。

### 2. 看市场：学生群体是最大的细分市场

- 需求场景集中在开学、期末、考试、四六级、教资、论文这几个节点，量非常大；
- 付费意愿低，但对「免费、无需注册、打开就用」极度敏感；
- 传播靠同学之间分享链接，而不是应用商店——**网页应用天然适合这个传播路径**。

**结论**：不需要商业化。一个能部署在 GitHub Pages 上、点开就能用的静态网页，就是这个市场里最合适的形态。

### 3. 看客户：大学生「立 flag 之后就没下文」

访谈与观察到的典型行为：

| 现状 | 痛点 |
| --- | --- |
| 立目标时用备忘录写一句「这学期要过六级」 | 目标太大，没有下一步动作 |
| 过两周想起来，已经忘了当初立过 | 缺少回顾入口 |
| 用过 Notion / 滴答清单，最后都吃灰 | 配置成本高、需要登录、提醒烦人 |
| 打卡类 App 断签就彻底放弃 | 一次中断等于全部清零，负反馈太强 |

**结论**：产品要解决的核心不是「记录」，而是**「把大目标拆成今天能做的小任务，并且让每一小步都有即时反馈」**。三个抓手：拆解、打卡、经验值。

### 4. 看竞争：不做「功能对打」，做「场景差异」

| 产品 | 优势 | 我们的差异 |
| --- | --- | --- |
| Notion / 飞书文档 | 自由、强大 | 我们零配置，打开就是目标+任务两栏，不需要搭模板 |
| 滴答清单 / Todoist | 任务管理成熟 | 我们强制「任务必须挂在目标下」，先有目标再有任务 |
| Forest / 番茄ToDo | 专注与成就感强 | 我们的成就感来自经验等级和连续天数，不绑定手机使用 |
| 纸质手账 | 无干扰、有仪式感 | 我们有统计和热力图，且不用带本子 |
| 微信小程序打卡 | 社交压力强 | 我们不社交、不排名，只跟自己比 |

**结论**：竞争不是要把它们干掉，而是在「我不想注册、不想配置、只想记一下这学期要干什么」这个缝隙里做到最好。

### 5. 看自己：三人小组、课程周期、零预算

- 团队 3 人，两周左右的开发窗口，都是第一次做「产品级」而非「课程作业级」的东西；
- 没有服务器预算，没有设计资源，没有测试机矩阵；
- 优势是**离用户近**——我们自己就是目标用户，知道什么设计会让自己愿意第二天再打开。

**结论**：技术选型必须保守。HTML/CSS/JS + localStorage 是唯一能在两周内做出完整闭环、还能真部署上线的组合。任何需要构建、需要后端、需要账号体系的方案都应该砍掉。

## 二、三定

### 1. 定战略控制点：**「打开即用」+「数据自持」**

我们认为这个产品真正的护城河不是功能，而是两个别人不愿意做的约束：

1. **零后端、零构建、零依赖**：双击就能用，扔到任何静态托管上就能分享，永远不会「服务挂了」；
2. **数据只存在用户自己的浏览器里**：不需要注册，不会有隐私争议，导出就是一个 JSON 文件。

这两个约束会持续帮我们挡掉「要不要加个云同步」「要不要接个 AI」之类的功能膨胀，也让「交到 GitHub 上让别人能跑起来」成为一件顺理成章的事。

### 2. 定目标：以验收清单为唯一标准

不追求「功能多」，只追求**核心链路没有断点**。目标按 SMART 拆：

| 维度 | 目标 | 衡量方式 |
| --- | --- | --- |
| 可用性 | 双击 `index.html` 即可完整使用 | 验收第 1 条 |
| 完整性 | 目标 → 任务 → 打卡 → 经验 → 统计 形成闭环 | 验收第 2–10 条 |
| 健壮性 | 重复点击、撤销、删除、导入非法文件都不产生脏数据 | 验收第 5–6 条、附录 B |
| 体验 | 480 / 1024 / 1440 三档宽度无横向滚动 | 验收第 13 条 |
| 体积 | 首屏资源 < 200 KB，无第三方请求 | 构建产物统计 |
| 可交付 | 结构清晰、文档齐备、能直接推上 GitHub Pages | 仓库检查 |

### 3. 定策略：**先做减法，再做打磨**

**第一刀砍掉「看起来该有」的功能**：账号、云同步、提醒推送、社交、深色模式、多语言、子任务、标签、甘特图。这些都是好功能，但都不服务于「今天有没有完成一件小事」这个唯一目标。

**第二刀把剩下的事情做深**：

1. 目标与任务之间**强制关联**——没有目标就不能建任务，逼用户先想清楚「为什么做」；
2. 经验值**只加不减**——中断一天不会前功尽弃，降低放弃概率；
3. 所有操作都有**即时反馈**——Toast、进度条、等级提示，让每次点击都有回应；
4. 空状态**给出下一步动作**——不是「暂无数据」，而是「从一个这学期想完成的事情开始吧」。

**分工与节奏**（对应文档里的八个核心任务）：

- A 线（骨架 + 数据层 + PWA）：先把数据结构和写入口定死，后面所有模块都依赖它；
- B 线（目标 + 任务）：在数据层之上做 CRUD 与渲染，是交互量最大的部分；
- C 线（打卡 + 经验 + 统计）：纯计算，依赖 A 线的数据结构，可以和 B 线并行；
- D/E 线（文档 + 测试 + 交付）：贯穿全程，最后一周集中收口。

**验收策略**：功能自测用 `tests/logic-test.js` 覆盖计算类规则，交互类走 `tests/manual-checklist.md` 手工验收，再用真实浏览器在三种宽度下过一遍。

---

## 三、一句话总结

LifeLite 不试图成为「更好的待办 App」，它只回答一个问题：**这学期想完成的那件事，今天能做什么？**
